# LearnDL 第一阶段开发计划（v0.1–v0.6）

> 状态：已确认  
> 参考书籍：《深度学习入门2：自制框架》  
> 范围：v0.1–v0.6；v0.0 为项目基础版本  
> 原则：原理优先、循序渐进、简单实现、独立验证

## 1. 项目定位

LearnDL 是一个**以学习和理解深度学习底层原理为目标**的个人项目，不以替代 PyTorch、实现生产级框架或追求性能为目标。

第一阶段参考《深度学习入门2：自制框架》的前四阶段（步骤 1–51），以 Python + NumPy 从零实现简易深度学习框架，重点学习：

- 变量、函数、计算图、链式法则与自动微分；
- 复杂计算图、梯度累积、反向传播顺序和内存管理；
- 高阶自动微分及反向传播计算图；
- 多维张量、形状变换、广播和矩阵运算的梯度；
- 神经网络、参数管理、SGD 和训练流程；
- 分类损失、批量数据加载与 MNIST 训练。

**第一阶段以 v0.6 为终点。** 完成后先复盘学习成果，再决定是否进行 Adam、BatchNorm、CNN、RNN 等扩展；这些内容不属于当前承诺范围。

### 1.1 学习与实现原则

1. **以书为主线**：原则上按书籍顺序学习，不另建一套平行教程。
2. **实现可以与书保持一致**：沿用 `Variable`、`Function`、`Layer` 等术语和 DeZero 的基本设计；当前包名使用 `dezero`（对照教材；项目名仍为 LearnDL）。只在理解、测试或维护需要时做适度调整。
3. **理解重于复刻**：不仅让代码运行，还要理解关键数学依据、设计原因、梯度形状和边界情况。
4. **最小实现**：只实现当前学习目标必要的功能，不提前设计复杂架构。
5. **逐版演进**：后续版本基于已有代码扩展，不复制六份独立框架。
6. **便于单人维护**：减少文档、流程、依赖和抽象，优先保持代码清晰。
7. **验证优先**：核心梯度使用解析结果、数值梯度检查或参考框架交叉验证。

### 1.2 与其他学习项目的边界

- **LearnDL**：自研基础框架以理解自动微分和训练机制；主要使用 Python + NumPy。PyTorch 可用于对照结果，不作为框架实现的依赖。
- **LearnOCR、VLM 等项目**：使用 PyTorch 学习更高层的模型与算法，不要求用 LearnDL 实现实际复杂模型。

## 3. 版本详细计划

### 3.1 v0.1 — 自动微分基础

**书籍对应：** 步骤 1–10。

**核心问题：** 为什么通过计算图和链式法则可以自动计算复合函数的导数？

**实现内容：**

- [x] `Variable`：保存 NumPy 数据、梯度及创建者信息。
- [x] `Function`：建立前向计算和反向求导的基本接口。
- [x] `Square`、`Exp`：实现简单函数及连续调用。
- [x] `numerical_diff`：实现用于验证的数值微分。
- [x] 从手动反向传播过渡到自动反向传播。
- [x] 将反向传播由递归改为循环，并提供 `backward()`。
- [x] 编写基础单元测试和数值梯度检查。

**重点理解：**

- Variable 为什么记录创建它的 Function？
- 前向传播如何构建计算图？
- 链式法则如何对应反向传播？
- 循环实现与递归实现的区别是什么？
- 为什么数值梯度适合测试，而不适合直接用于实际训练？

**验收条件：**

- [x] 能组合 `Square` 和 `Exp` 构建简单复合函数。
- [x] 调用 `backward()` 能得到正确的一阶梯度。
- [x] 典型样例通过数值梯度检查，测试可重复运行。

**验收记录：** 2026-10-17 已复核现有示例与 `step10.py` 的 5 个单元测试，均通过；学习小结见 [`v0.1.md`](v0.1.md)。理解自检及 Git Tag 由维护者确认后完成。

**暂不做：** 加减乘除运算符重载、通用分支图和张量运算接口。

### 3.2 v0.2 — 复杂计算图与基础运算

**书籍对应：** 步骤 11–24。

**核心问题：** 为什么复杂计算图需要梯度累积和正确的反向传播顺序？

**实现内容：**

- [x] 将 `Function` 扩展为支持可变长输入与输出。
- [x] 实现加法，支持同一变量被重复使用时的梯度累积。
- [x] 使用 `generation` 管理复杂计算图的反向传播顺序。
- [x] 学习 Python 引用关系，使用 `weakref` 减少不必要的循环引用。
- [x] 实现无需保留计算图的模式（如 `no_grad`），并避免保留不必要的中间梯度。
- [x] 为 `Variable` 增加必要的常用属性、显示能力和运算符重载（`+`、`-`、`*`、`/`、`**` 及相应反向运算）。
- [x] 将已有代码整理为可正常导入的 `dezero` 包。
- [x] 补充复杂函数和分支计算图的回归测试。

**重点理解：**

- 为什么 `y = x + x` 必须累积梯度？
- 为什么仅按某一条分支反传可能得到错误结果？
- `generation` 如何决定反向传播顺序？
- Python 引用计数、循环引用和 `weakref` 的关系是什么？
- `no_grad` 为什么能减少计算图构建？

**验收条件：**

- [x] `y = x * x + x` 等自然表达式正确求导。
- [x] 分支、共享变量、多输入与多输出的典型用例通过测试。
- [x] 代码可以通过 `import dezero` 使用，v0.1 测试继续通过。

**验收记录（2026-10-19）：** v0.2 核心代码、教学脚本与回归测试复核通过；版本总结见 [`v0.2.md`](v0.2.md)。由维护者执行最终提交与 Git Tag。

**暂不做：** 独立执行引擎、算子注册体系、复杂内存管理系统。

### 3.3 v0.3 — 高阶自动微分

**书籍对应：** 步骤 25–36。

**核心问题：** 为什么反向传播过程本身也可以构建新的计算图，并继续求导？

**实现内容：**

- [ ] 理解计算图可视化；按需要实现最简 Graphviz/DOT 输出用于调试。
- [ ] 使用 Rosenbrock 函数等示例理解梯度下降和牛顿法的原理。
- [ ] 调整反向传播实现，使其能够在需要时构建计算图。
- [ ] 实现 `create_graph` 等必要模式控制机制。
- [ ] 实现/补充 `sin`、`cos`、`tanh` 等验证高阶导数所需运算。
- [ ] 编写二阶求导、牛顿法和 double backprop 的最小示例。
- [ ] 检查高阶求导与既有一阶求导功能的兼容性。

**重点理解：**

- 反向传播中的计算为什么仍然是可微运算？
- 什么情况下应保留反向传播的计算图？
- 一阶梯度如何继续求导得到二阶梯度？
- 高阶求导的计算图与普通前向计算图有何区别？

**验收条件：**

- [ ] 能正确计算并验证 `f(x)=x^4` 的一阶及二阶导数。
- [ ] 至少一个较复杂函数的高阶求导示例通过测试。
- [ ] v0.1–v0.2 的一阶求导和计算图测试继续通过。

**暂不做：** 通用 Hessian/Jacobian API、二阶优化器库、复杂可视化系统。

### 3.4 v0.4 — 张量运算与自动微分

**书籍对应：** 步骤 37–41。

**核心问题：** 张量的形状变化、求和、广播和矩阵乘法为什么会以不同方式传递梯度？

**实现内容：**

- [ ] 将 `Variable` 的应用扩展到多维 NumPy 数组。
- [ ] 实现 `reshape` 与 `transpose` 的前向和反向传播。
- [ ] 实现 `sum`，正确处理 `axis` 和 `keepdims`。
- [ ] 实现 `broadcast_to`、`sum_to` 及广播运算的梯度归约。
- [ ] 实现矩阵乘法 `matmul` 及反向传播。
- [ ] 增加张量形状、广播、归约、矩阵乘法的梯度测试。

**重点理解：**

- 为什么梯度的形状必须与对应输入的形状匹配？
- `reshape` 与 `transpose` 的反向传播如何还原形状？
- 广播的反向传播为什么需要沿特定维度求和？
- 矩阵乘法的梯度为何涉及矩阵转置？

**验收条件：**

- [ ] 形状变换、归约、广播和矩阵乘法的前向结果正确。
- [ ] 相应梯度数值及形状正确，通过数值梯度检查。
- [ ] 典型结果可与 NumPy 或 PyTorch 对照；既有测试继续通过。

**暂不做：** GPU、多后端、自定义存储结构、完整 NumPy API。

### 3.5 v0.5 — 神经网络与 SGD

**书籍对应：** 步骤 42–46。

**核心问题：** 如何将自动微分得到的梯度用于优化参数和训练神经网络？

**实现内容：**

- [ ] 实现 `mean_squared_error` 及线性回归示例。
- [ ] 实现 `linear` 和必要的激活函数。
- [ ] 实现最简 `Parameter`、`Layer`、`Linear`。
- [ ] 实现最简 `Model`、`MLP`，支持网络参数管理。
- [ ] 实现 `Optimizer` 和 `SGD`。
- [ ] 使用最简训练循环训练线性回归及 MLP。
- [ ] 验证梯度清理、参数更新与损失变化。

**重点理解：**

- 为什么需要非线性激活函数？
- `Parameter` 与 `Variable` 有何区别？
- SGD 为什么沿负梯度方向更新参数？
- 学习率对训练结果有什么影响？

**验收条件：**

## 4. 每个版本的统一工作方式

各版本遵循同一套简单流程，无需另建复杂的项目管理体系：

1. **阅读书籍**：按对应步骤学习，明确作者解决的问题及基本思路。
2. **实现代码**：参考书籍逐步编写；可以与书中一致，不刻意重构。
3. **验证结果**：补充关键单元测试、梯度检查和可运行示例。
4. **记录理解**：简要记录原理、困惑、易错点和必要的取舍，不重复抄写教材。
5. **完成版本**：整理临时代码，确认测试通过，提交代码并创建 Git Tag。

### 4.1 通用版本完成标准

- [ ] 本版本的必要功能已经实现并可正常使用。
- [ ] 核心计算和梯度测试通过，已有版本的回归测试通过。
- [ ] 至少有一个体现本版知识重点的可运行示例。
- [ ] 已理解主要原理，并完成简短学习总结。
- [ ] 清理明显的临时代码后，提交并标记版本。

**说明：** 版本没有固定截止日期。遇到重要原理尚未理解时，优先继续学习，而不是为了推进版本号降低验收要求。

## 6. 第一阶段范围限制

明确**不将以下事项作为 v0.1–v0.6 的目标**：

- 兼容 PyTorch API，或替代 PyTorch；
- 多后端、多设备、C++/Python 双实现；
- GPU、CuPy、性能优化和生产级部署；
- Adam、BatchNorm、Dropout、CNN、VGG16、RNN、LSTM；
- 完整的训练器、插件系统、复杂配置系统或通用算子框架；
- 大量与学习目标无关的架构、流程和文档。

如果某项额外能力是当前学习内容所必需的，可加入**最小实现**，但不因此扩张整体目标。

## 7. 第一阶段结束与后续决策

当 v0.6 完成并通过验收时，LearnDL 第一阶段结束。届时先回答三个问题：

2. 哪些知识仍不扎实，值得回头做更小的实验？
3. 是否有必要继续学习 Adam、BatchNorm、CNN 等专题？
